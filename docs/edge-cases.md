# Edge Cases

Please ee `docs/product-decisions.md` for the fuller reasoning behind the cases involving explicit product or design decisions.

| Area            | Edge case                                                | Handling                                                                                                                                                                                    |
| --------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Enrolment**   | Duplicate email                                          | Rejected - database unique constraint plus a friendly 400/409 response rather than exposing a raw database error.                                                                           |
|                 | Future date of birth                                     | Rejected at the API layer.                                                                                                                                                                  |
|                 | Implausible date of birth                                | Rejected using a minimum-age check of 5 years as of January 1 of the enrolment year.                                                                                                        |
|                 | Duplicate Student ID                                     | Prevented structurally using an atomic database counter rather than application-level counting.                                                                                             |
|                 | Two admins create students simultaneously                | Handled - `IdCounter` is incremented using a single atomic SQL statement.                                                                                                                   |
|                 | Non-existent programme selected                          | Rejected with a 400 response before the student is created.                                                                                                                                 |
|                 | Invalid academic year or status                          | Rejected with a specific validation message rather than a generic 500 error.                                                                                                                |
|                 | Withdrawn student accidentally reset to Enrolled         | Not specifically blocked. The brief defines four allowed statuses but does not define institutional status-transition rules, so no additional progression rules are enforced.               |
| **Fees**        | Zero or negative payment                                 | Rejected.                                                                                                                                                                                   |
|                 | Payment exceeds outstanding balance                      | Rejected with 409 - deliberate no-overpayment policy.                                                                                                                                       |
|                 | Duplicate payment reference number                       | Rejected using a database unique constraint.                                                                                                                                                |
|                 | Two simultaneous payments against the same student       | Handled using a `SERIALIZABLE` transaction. If a concurrent transaction loses the race, it receives a 409 response asking the caller to retry rather than silently overdrawing the account. |
|                 | Positive balance but due date has not passed             | Shown as **outstanding**, not **overdue**. These are deliberately treated as different states.                                                                                              |
|                 | Withdrawn/deferred student with an unpaid balance        | Still surfaced as overdue on the dashboard. Enrolment status does not remove an outstanding financial obligation.                                                                           |
|                 | Programme fee changes after enrolment                    | Existing students retain their original `assignedFee`; only new enrolments use the updated programme fee.                                                                                   |
|                 | Payment recorded for a non-existent student              | Rejected with 404 before any write occurs.                                                                                                                                                  |
| **Submissions** | Wrong file type                                          | Rejected - both file extension and MIME type are checked.                                                                                                                                   |
|                 | Oversized file                                           | Rejected - maximum file size is 10 MB.                                                                                                                                                      |
|                 | Empty file                                               | Rejected - zero-byte files are not accepted.                                                                                                                                                |
|                 | Late submission                                          | Accepted and flagged as late. Being late alone does not prevent submission because the brief does not require that behaviour.                                                               |
|                 | Resubmission before deadline                             | Accepted - the existing submission is replaced.                                                                                                                                             |
|                 | Resubmission after deadline                              | Rejected with 403. A first-time late submission is allowed, but an existing submission cannot be replaced after the deadline.                                                               |
|                 | Student submits to an assessment outside their programme | Rejected with 403.                                                                                                                                                                          |
|                 | Student submits using another student's ID               | Rejected - the server derives the student identity from the authenticated session rather than trusting the request body.                                                                    |
|                 | Submission exactly at the deadline                       | Evaluated using server time rather than the client's clock.                                                                                                                                 |
| **Grades**      | Score outside 0–100                                      | Rejected both client-side and server-side. Server-side validation is authoritative.                                                                                                         |
|                 | Non-integer score                                        | Rejected both client-side and server-side.                                                                                                                                                  |
|                 | No submission exists                                     | Cannot be graded - a grade requires an associated submission.                                                                                                                               |
|                 | Grade of exactly 0                                       | Valid. A zero is a genuine Fail and is distinct from "not graded".                                                                                                                          |
|                 | Editing an already-published grade                       | Rejected with 409 unless the grade is withheld first.                                                                                                                                       |
|                 | Late submission receives a high score                    | Allowed. Lateness is recorded separately and is not automatically treated as an academic penalty.                                                                                           |
| **Results**     | Unpublished grade                                        | Excluded at the database query level using `publishedAt: { not: null }`, rather than merely hiding it in the UI.                                                                            |
|                 | Withheld vs. not graded                                  | Modelled as distinct states rather than conflated.                                                                                                                                          |
| **Security**    | Student visits a staff URL                               | Redirected by middleware before the page renders.                                                                                                                                           |
|                 | Student visits another student's URL                     | Redirected to their own student record.                                                                                                                                                     |
|                 | Direct API call bypasses the UI                          | Rejected independently by the API's session/role checks. Middleware alone is not relied upon for API protection.                                                                            |
|                 | Client attempts to set Student ID, balance, or grade     | Ignored/rejected - these values are server-controlled and are never trusted from request bodies.                                                                                            |
| **General**     | Database or network failure during a request             | Handled by route-level error handling and Next.js error boundaries rather than allowing an unhandled crash.                                                                                 |
|                 | Non-existent record requested by ID                      | Returns 404 with an appropriate response rather than a generic 500 or silent empty page.                                                                                                    |
